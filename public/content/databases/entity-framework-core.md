An **object-relational mapper (ORM)** bridges objects in your code and rows in a relational database. You query and save objects; the ORM generates the SQL. Examples: **Entity Framework Core** (.NET), Hibernate (Java), Prisma and TypeORM (TypeScript), SQLAlchemy (Python).

> [!NOTE]
> **Entity Framework 6** is the older ORM for .NET Framework and is in maintenance. **EF Core** is the modern, cross-platform rewrite and the one to use for new work.

## Mapping classes to tables

```csharp
public class Order
{
    public Guid Id { get; set; }
    public DateTime CreatedAt { get; set; }
    public List<OrderLine> Lines { get; set; } = [];
}

public class ShopContext(DbContextOptions<ShopContext> options) : DbContext(options)
{
    public DbSet<Order> Orders => Set<Order>();

    protected override void OnModelCreating(ModelBuilder model) =>
        model.Entity<Order>().HasIndex(o => o.CreatedAt);
}
```

## Querying with LINQ

```csharp
var recent = await db.Orders
    .Where(o => o.CreatedAt >= since)
    .OrderByDescending(o => o.CreatedAt)
    .Select(o => new { o.Id, LineCount = o.Lines.Count })   // project only what you need
    .AsNoTracking()                                          // read-only: skip change tracking
    .ToListAsync();
```

The LINQ expression is translated to SQL and runs **in the database** — until you call something that can't be translated or you enumerate early (`ToList()` before `Where`), after which the work happens in memory.

## Migrations

```bash
dotnet ef migrations add AddOrderCreatedAtIndex
dotnet ef database update
```

Migrations version your schema alongside your code. Review the generated SQL (`dotnet ef migrations script`) before running it in production.

## Performance traps

- **N+1 queries** — lazily loading `order.Lines` inside a loop issues one query per order. Use `Include`, projection or a single query.
- **Fetching whole entities** when you need two columns — project with `Select`.
- **Tracking read-only data** — use `AsNoTracking()`.
- **Client-side evaluation** — filtering after `ToList()` pulls the whole table into memory.

> [!AI]
> ORM code generated by assistants often compiles and returns the right answer while hiding N+1 queries. Enable SQL logging (`LogTo(Console.WriteLine)`) in development and look at what actually runs.

```recall
Q: What does an ORM do?
A: Maps between objects in application code and rows in relational tables, generating SQL for queries and saves.

Q: Should new .NET projects use EF6 or EF Core?
A: EF Core — EF6 targets .NET Framework and is in maintenance mode.

Q: What is the N+1 query problem?
A: Loading a list (1 query) and then lazily loading related data per item (N more queries), instead of fetching everything in one or a few queries.

Q: What does AsNoTracking() do and when should you use it?
A: It skips EF Core's change tracking; use it for read-only queries to save memory and CPU.
```
